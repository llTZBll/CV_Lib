# class3_openCV：答题卡自动识别与预处理（OpenCV 综合实战）

## 1. 任务目标

对答题卡图像完成从“读取 → 几何矫正 → 核心区域定位裁剪 → 降噪/二值化/形态学 → 涂卡识别 → 结果可视化”的完整流程，并输出每一步的处理结果图。

- **最终效果**：在本次样张上实现 **客观题（85 题）识别准确率 100%**  
- **结果输出**：所有中间结果统一保存到 `class3_openCV/answer_card_result/`

## 3. 运行方式

在 `class3_openCV` 目录下运行：

```bash
python answer_card_process.py
```

也可以传入图片路径（Windows 中文路径也支持）：

```bash
python answer_card_process.py "DataSets/answer_card/1.png"
```

依赖：

- `opencv-python`
- `numpy`

### 4.3 核心创新点：自适应“裁剪识别”（04）

传统作业模板常用“固定比例裁剪”（例如 \(W/6 \sim 5W/6\)、\(H/6 \sim 5H/6\)），对不同拍摄距离、偏移、旋转后边界留白不稳定：  
一旦裁剪偏了，后续“答案框坐标写死”的方案会整体漂移，导致识别失败。

本实现将 **“裁剪”做成自适应定位**，直接以“答题区结构特征”为锚点，稳定得到 `img_cropped`（也就是后续一切坐标的基准坐标系）。

实现思路（对应 `answer_card_process.py` 的 `basic_operation()`）：

- **(1) 以灰度阈值提取“深色像素”**：  
  将灰度图中较暗部分视为 1（包含粗分隔线、涂黑选项、右侧条码等），得到 `dark`。
- **(2) 行投影定位“粗横分隔线”**：  
  在上半区域（排除标题/准考证号）对 `dark` 按行求和，峰值行通常对应答题区上方的粗横线；据此得到 `crop_h_start`，将答题区上沿稳定对齐。
- **(3) 列投影定位右侧条码区并裁掉**：  
  在图像右侧（约 65% 以后）对 `dark` 按列求和，条码列“极黑且很高”，用阈值筛出条码起始列，得到 `crop_w_end`，自动裁掉条码区，避免干扰与坐标漂移。
- **(4) 内容外接范围收紧左/下边界**：  
  对全图列/行投影找出“有内容的列/行”，适当 padding 后作为 `crop_w_start` 与 `crop_h_end`，减少空白边缘，提高后续阈值与形态学的稳定性。
- **(5) 安全夹取与兜底**：  
  对所有边界做 `clip`，避免极端情况越界崩溃。

## 5. 答案识别方法概述（与 21/22 对应）

识别模块 `extract_answers_85()` 的核心做法：

- **二值化（涂黑为白）**：对双边滤波灰度图做 `THRESH_BINARY_INV`，再做开闭运算，得到 `21-答题卡二值_涂黑为白.jpg`
- **答案框布局**：函数 `_gen_answer_layout_85()` 生成 85 题 A/B/C/D 的 ROI 坐标（以 04 裁剪图为坐标系，便于一次对齐后稳定复用）
- **判定策略**：对每个 ROI 计算白像素占比（填涂覆盖率），超过 `min_fill_ratio` 即判为所选
